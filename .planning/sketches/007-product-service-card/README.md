# Sketch 007: Карточка товара/услуги

## Design Question

Владельцу не нравится сегодняшняя карточка. Диагноз по префабу (`Product.prefab` /
`Service.prefab`, вьюхи `ProductCardView`/`ServiceCardView`):

- **Серый квадрат-заглушка 160×160** с одной и той же иконкой на каждой строке.
  Фото у товаров в данных **нет вообще** (модель = название/цена/описание) — квадрат
  не несёт информации и съедает треть ширины, из-за чего название режется
  («Колодки Bosch п…»).
- **Цена мелкая**, прижата к шеврону справа — а для карточки-«ценника» это главное
  значение после названия.
- **Описание** — одна обрезанная строка мелким серым.
- Карточка-плашка с тенью на каждую позицию — визуальный шум при 5+ позициях.

Вопрос скетча: что из этого лечится плотностью (реестр), что — обогащением
(монограмма+ценник), а что — сменой жанра (витрина)?

## How to View

open .planning/sketches/007-product-service-card/index.html

Темы: тёмная (дефолт приложения) / светлая — переключатель внизу справа.
Всё живое: вкладки «Продукты»/«Услуги» кликабельны, тап по карточке открывает
шит редактирования (Название/Цена/Описание — как настоящий `ItemEditSheet`),
«Готово» применяет правки во все варианты сразу, «Удалить» удаляет.
«Очистить список» в тулбаре показывает empty state каждого варианта.

## Variants

- **Baseline: Сегодня** — воспроизведение текущей карточки: заглушка-квадрат, имя+описание в одну строку, цена у шеврона. Точка отсчёта.
- **A: Реестр** — муляж удалён совсем; одна сгруппированная карточка, строки через hairline (iOS Settings/Wallet). Цена — табличные цифры справа, заголовок-счётчик «5 товаров». Самый тихий и самый плотный (~8 позиций на экран).
- **B: Ценник ★ (выбран, раунд 1)** — отдельные карточки остаются; вместо заглушки — цветная монограмма (детерминированный цвет от названия, 6 оттенков), цена — пилюля accent-soft. Имя и описание до 2 строк. «Тёплый каталог».
- **C: Витрина** — сетка 2 колонки как мини-маркетплейс: цветная зона с монограммой сверху, название, крупная цена внизу. Описание в карточке не показывается. Плитка-призрак «+ Добавить». Заодно отвечает на вопрос «нужны ли товарам фото» — зона под них уже есть.

## Round 2 — B + прайс-листы наверху (по правке владельца)

Владелец выбрал B и попросил показать вкладку целиком: список загруженных
прайс-листов наверху, до товаров (как сегодня), плюс кнопка «Загрузить
прайс-лист». Анатомия строки взята 1:1 из реального приложения
(`BotSettingsUploadedFilesBuilder` / `BotSettings.Files.cs`): бейдж-расширение
37×37, имя, «размер · дата», ✕ с confirm-текстом «Бот перестанет
использовать…»; при загрузке ✕ сменяется пульсирующими точками, meta —
«Загрузка…». Кнопка открывает реальный источник-шит «Файл / Фото из галереи /
Отмена».

- **B2: + прайсы (секция)** — сегодняшняя структура в языке B: заголовок
  «ПРАЙС-ЛИСТЫ», одна группа со строками файлов через hairline, «Загрузить
  прайс-лист» — строка внутри группы; ниже заголовок «ТОВАРЫ» и карточки B.
  Смысловой цветовой код: документы = акцент, товары = цветные монограммы.
- **B3: + прайсы (чипы)** — прайсы сжаты в полку чипов (расширение + имя + ✕,
  чип «+ Загрузить» с dashed-рамкой); товары начинаются на ~100 px выше.
  Плата: размер · дата скрыты, длинные имена режутся, цель ✕ меньше.

## What to Look For

- **Муляж vs монограмма vs ничего:** квадрат-заглушка (baseline) против цветной
  буквы (B/C) против чистого текста (A). Что честнее для данных без фото?
- **Цена:** где она читается быстрее — строкой справа (A), пилюлей (B) или крупно
  под названием (C)? В C цена крупнее имени — витринная логика.
- **Длинные названия:** baseline режет «Колодки Bosch п…», A даёт одну полную
  строку, B переносит на две. Реальные названия запчастей длинные — критерий важный.
- **Плотность:** A ≈ 8 позиций на экран, B ≈ 4–5, C ≈ 4 (по 2 в ряд). Сколько
  позиций у реального владельца? При 3–5 витрина C выглядит богаче; при 20 — утомит.
- **Описание:** A/B показывают (1 и 2 строки), C прячет в редактор. Терпимо ли
  «за деталями — тап»?
- **Услуги:** переключите вкладку — у услуг нет «товарного лица», проверьте, не
  выглядит ли витрина C для них натянуто.

## What to Look For — round 2

- **Сколько экрана отдать документам:** B2 с тремя файлами занимает ~⅓ экрана
  до первого товара; B3 — вдвое меньше. Сколько файлов у реального владельца?
- **Различимость сущностей:** файлы (акцентные бейджи, группа/чипы) против
  товаров (цветные монограммы, отдельные карточки) — считывается ли «это
  корм для бота, а это каталог»?
- **Метаданные файла:** B3 прячет размер · дату. Нужны ли они владельцу чаще,
  чем раз в месяц?
- **Живые потоки:** «Загрузить прайс-лист» → шит источника → строка «Загрузка…»
  с точками → готово; ✕ → confirm. Проверьте оба варианта.
