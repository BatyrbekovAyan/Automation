# Подачный пакет для сторов (store submission pack) — дизайн

**Дата:** 2026-08-27 · **Статус:** утверждено владельцем (вопрос-раунд 2026-08-27: скоуп одобрен, хостинг = свой домен владельца, имя приложения будет заменено с рабочего «Automation»)
**Контекст:** владелец хочет подать приложение в App Store / Google Play как можно раньше, НЕ дожидаясь Блока 2. Разбор показал: из 16 задач Блока 2 для ПОДАЧИ не нужна ни одна — ревью-путь (свежая установка → онбординг → триал → пейволл → sandbox-покупка → restore) их не касается. Блокируют подачу вещи, которых нет ни в одном блоке: юр-ссылки у точки покупки (Apple Guideline 3.1.2), сами юр-документы с публичными URL и сопровождение ревью. Правило запуска Блока 1 §7 не трогается: ПУБЛИЧНЫЙ релиз с пейволлом — по-прежнему только после Блока 2 (задачи 0–5).

## 1. Скоуп

Три куска, ничего больше:

- **A. Код (Unity):** юр-ссылки «Условия использования» · «Политика конфиденциальности» в футере пейволла + корректный fine-print об автопродлении в состоянии «Оформить…».
- **B. Юр-документы (RU):** политика конфиденциальности + условия использования, готовые HTML для выкладки на домен владельца.
- **C. Стор-пакет (`docs/store/`):** чеклист подачи по обеим консолям, review notes для Apple (EN), сценарий демо-видео, ответы privacy labels / Data Safety.

**Не делаем:** задачи Блока 2 (все 16 остаются в своём плане); встроенные in-app юр-страницы (хостинг обязателен в любом случае — App Store Connect требует Privacy Policy URL в метаданных, а `ProfileSubPagesBuilder` деструктивен для новых страниц); действия в консолях сторов (владелец, по чеклисту).

## 2. Открытые входы (ждут владельца, всё остальное от них не зависит)

1. **Имя приложения** — рабочее «Automation» до замены; в юр-текстах имя встречается минимально (шапка + одно определение «далее — „Приложение"»), замена = точечная правка.
2. **Домен** — URL юр-страниц (`https://<домен>/privacy`, `https://<домен>/terms`). До получения: `LegalLinks.TermsUrl`/`PrivacyUrl` пустые → юр-ряд на пейволле СКРЫТ (не рендерим мёртвые ссылки), а чеклист держит «URL заполнены и открываются» красным блокером подачи.

## 3. Дизайн A — код

- **`Assets/Scripts/Billing/LegalLinks.cs`** — новый pure-seam: `TermsUrl`/`PrivacyUrl` (константы, сейчас `""`), `HasUrls => обе непустые`, `TermsLabel = "Условия использования"`, `PrivacyLabel = "Политика конфиденциальности"`, разделитель ряда «·». Единственное место, куда владелец вписывает домен.
- **`PaywallRows.FinePrintText(bool isTrialOffer)`** — трал-состояние: сегодняшний `FinePrint` («Без карты · Отмена в любой момент»); состояние покупки: «Подписка продлевается автоматически. Отменить можно в настройках App Store / Google Play в любой момент.» Apple 3.1.2 требует ясности об автопродлении у точки покупки; текущая строка в состоянии «Оформить…» этого не говорит.
- **`PaywallController`:** два новых `[SerializeField] Button` (terms/privacy) + `GameObject legalRow`; клики → `Application.OpenURL`; `legalRow.SetActive(LegalLinks.HasUrls)` в `Refresh`; fine-print берётся из `FinePrintText` по тому же `IsTrialOffer`, что уже управляет CTA.
- **`Assets/Editor/PaywallLegalRowBuilder.cs`** — ОТДЕЛЬНЫЙ аддитивный идемпотентный билдер (паттерн ItemEditSheetRestyleBuilder; полный `PaywallBuilder` не перезапускаем — сцена источник истины): под `BottomBar` после `Restore` создаёт `LegalRow` (HorizontalLayout: кнопка-лейбл · точка · кнопка-лейбл), стиль клонирует с Restore (шрифт/тема-байндинг), кегль 30, `ThemeRole.InkTertiary`, alpha-0 hit-area ≥ 88u высотой по паттерну Restore; правит `PaywallController`-refs через `SerializedObject`; headless-вход `BuildHeadless`.
- **Тесты:** `LegalLinksTests` (лейблы непусты; URL либо пустой, либо `https://` без пробелов; `HasUrls`-матрица), `PaywallRowsTests` дополняется пином `FinePrintText` обоих состояний; `FontGlyphCoverageTests` — новый seam в списке (тексты против SF Pro: «·» U+00B7 в атласе есть).

## 4. Дизайн B — юр-документы

`docs/legal/privacy.html` + `docs/legal/terms.html` — самодостаточные HTML (встроенный CSS, мобильная вёрстка, RU), готовые к выкладке на домен как есть.

**Политика (честная, по фактическим потокам):** оператор — владелец (реквизиты: контактный e-mail; поле юрлица/ИП помечено к заполнению владельцем до выкладки); какие данные: содержимое переписок клиентов пользователя (WhatsApp/Telegram через подключённые профили Wappi), загруженные прайс-листы (файлы/фото), настройки бизнеса; куда идут: Wappi (транспорт сообщений), n8n + OpenAI (генерация ответов/подсказок/классификация итогов), Supabase (истории диалогов, итоги, чанки и оригиналы прайс-листов), RevenueCat (анонимный ID покупок, статус подписки); чего НЕТ: рекламы, трекинга, продажи данных, сбора данных без действия пользователя; хранение/удаление: «Удалить все данные» в приложении + запрос по e-mail; ответственность пользователя за согласие своих клиентов на автоматизированную обработку переписки.

**Условия:** подписка через сторы (тарифы/цены — в приложении), автопродление и отмена в настройках стора, триал 5 дней; сервис использует НЕОФИЦИАЛЬНЫЕ интеграции WhatsApp/Telegram через Wappi — риск ограничений аккаунта мессенджером лежит на пользователе (ключевой честный пункт для этого продукта); допустимое использование (никакого спама/рассылок по чужим контактам); отказ от гарантий/ограничение ответственности; изменения условий.

## 5. Дизайн C — стор-пакет (`docs/store/`)

- **`submission-checklist.md`** — единый чеклист: блокеры (URL юр-страниц живые; имя финальное; скриншоты; демо-видео записано), App Store Connect по шагам (privacy labels с ГОТОВЫМИ ответами под факты приложения; subscription group + 7 SKU уже заведены Блоком 1 — сверка; Privacy Policy URL; ревью-поля с приложенными notes), Play Console по шагам (Data Safety с готовыми ответами, IARC, **предупреждение: личный аккаунт после ноября 2023 = обязательный closed test ~2 недели — проверить тип аккаунта и стартовать НЕМЕДЛЕННО, если применимо**), Apple Small Business Program (заявка после активации), пометка manual release.
- **`app-review-notes.md`** — EN-текст для поля Review Notes: что делает приложение, почему ревьюер не может пройти WhatsApp-авторизацию сам (нужен живой номер с телефоном рядом — поэтому демо-видео), как проверить триал/пейволл/покупку в sandbox, что триал — app-level (не StoreKit intro offer) и не запрашивает оплату вне IAP.
- **`demo-video-script.md`** — 90-секундный сценарий: создание бота → QR-авторизация WhatsApp → входящее сообщение клиента → автоответ ИИ → режим «Вместе» → Сводка → пейволл.

## 6. Порядок и верификация

1. `LegalLinks` + `FinePrintText` + тесты (pure, EditMode).
2. `PaywallController` wiring.
3. `PaywallLegalRowBuilder` + прогон билдера + сохранение сцены (немедленный коммит сцены — правило parallel-scene-clobber).
4. `FontGlyphCoverageTests` seam.
5. Юр-документы + стор-пакет.
6. Полный EditMode-прогон (bridge/headless), сверка билдера по артефакту в сцене.

Готово = тесты зелёные, юр-ряд виден на пейволле при заполненных URL и скрыт при пустых, документы читаются владельцем, чеклист исполним без меня.
