# Премиальный лендинг choosereply.com (v2) — дизайн-спека

Дата: 2026-09-19. Статус: одобрено владельцем (чат: бренд «как в приложении», направление
«Гибрид А+В+Б», дизайн «Да, делай»). Предшественник: одностраничник v1
(`docs/superpowers/specs/2026-08-27-landing-page-design.md`), живой с 2026-08-28.

## Цель

Владелец: «очень крутой премиальный сайт — каждый, кто зайдёт, в восторге; крутые анимации
и эффекты; но чтобы сайт не зависал». Две жёсткие цели равного веса:

1. **Вау** — эффект с первой секунды и на всём пути прокрутки.
2. **Не зависает** — плавно на слабом Android, быстрый первый экран.

Плюс неизменные требования v1: собирать заявки на ранний доступ до выхода в сторах;
юридические страницы на вшитых в приложение путях.

## Исследование (прототипы)

`.planning/sketches/008-premium-landing/` — бриф `BRIEF.md`, три прототипа, общий набор
ассетов и headless-стенд `_harness/shoot.mjs` (playwright-core + системный Chrome:
скриншоты 390×844@2× и 1440×900 на точках прокрутки, FPS при 4× CPU-throttle, ошибки
консоли, вес). Замеры 2026-09-19 (машина под сильной посторонней нагрузкой, load avg 11–30;
текущий сайт v1 в тех же условиях — 58 FPS):

| Прототип | Суть | Mobile 4× FPS / p95 / кадры > 50 мс |
|---|---|---|
| А «Кинематограф» | «Выбери … ответ.», pinned 3D-телефон с настоящими экранами | 59 / 17 мс / 0 |
| Б «Живой диалог» | интерактивная переписка, «Авто/Вместе», ниши, WebGL-аврора | 21 / 167 мс / 19 |
| В «Сигнал» | частицы (raw WebGL) → знак → пузыри → WhatsApp/Telegram | 35 / 83 мс / 20 |

Решение: **гибрид** — основа А (скорость, типографика, pinned-история), первый экран —
частицы В (с деградацией), секция «Попробуйте сами» — из Б.

## Структура страницы (одна страница, RU)

1. **Шапка** — стекло (backdrop-filter только там, где дёшево; на слабом уровне — сплошной
   фон), знак + «Choose Reply», меню (Как работает · Попробуйте · Тарифы · Вопросы), CTA
   «Ранний доступ» (магнитная на desktop, pointer:fine).
2. **Hero** — H1 «Ответ — за ботом. Выбор — за вами.»; подзаголовок про WhatsApp/Telegram
   с вашего номера по вашему прайсу, 24/7, «Авто» или до 4 вариантов на выбор; CTA; микро-
   строка «5 дней бесплатно · 150 диалогов · без карты»; бейджи App Store / Google Play
   «скоро». Визуал: частицы собираются в знак (средняя полоса ярче), курсор/касание их
   расталкивает. LCP — текст H1, не canvas.
3. **Переход «Сигнал»** — на прокрутке частицы перетекают в пузыри «клиент пишет → бот
   отвечает», затем в пару знаков WhatsApp/Telegram («Один номер — два мессенджера»).
4. **История с телефоном** — pinned-сцена: 3D-телефон, экраны сменяются 01 чаты → 02
   «Вместе» (панель «Предложения») → 03 прайс-листы и каталог → 04 «Сводка» с плавающими
   статус-чипами; слева заголовки по словам, прогресс-индикатор 01–04.
5. **«Попробуйте сами»** — интерактивное демо: вкладки ниш (Автозапчасти, Цветы,
   Kaspi-продавец, Ремонт телефонов), переписка с индикатором «печатает…», карточки
   вариантов (ЦЕНА И АРТИКУЛ / ДЕШЕВЛЕ / ПРО ЗАМЕНУ / ОФОРМИТЬ? и т. п.), клик/тап по карточке
   отправляет её пузырём с ✓✓; переключатель «Вместе / Авто» (в «Авто» бот отвечает сам с
   пометкой). `aria-live` для новых сообщений; работает с клавиатуры.
6. **Ниши** — бегущая лента (CSS-анимация, пауза вне экрана) + 6 карточек с примером
   вопроса клиента и тем, что делает бот.
7. **Подключение за 3 шага** — номер по QR/коду → прайс → бот отвечает.
8. **Тарифы** — переключатель «Месяц / Год», цифры анимированно «докручиваются»; баннер
   пробного периода; 3 плана (Бизнес — «Популярный»); строка о докупке 500 диалогов за
   3 900 ₸ и оплате подпиской в приложении, отмена в любой момент.
9. **Вопросы и ответы** — аккордеон `<details>` (работает без JS), 5–6 честных ответов
   (см. «Правдивость»).
10. **Финал + форма** — огромное кинетическое «Выбери ответ.» и форма заявки (контракт
    v1 без изменений, см. ниже); успех — анимация «выбранной полосы».
11. **Подвал** — знак, «Сделано в Казахстане», © 2026 Choose Reply, `/privacy.html`,
    `/terms.html`.

## Правдивость (жёстко)

Нельзя: отзывы, логотипы клиентов, «N компаний», проценты роста, «отвечает за N секунд»,
рейтинги сторов, интеграции с Kaspi/1С/CRM, «понимает казахский», «передаёт диалог и
ставит бота на паузу» (стадия A5/A6 не развёрнута).
Можно (подтверждено кодом/политикой): 24/7; с номера владельца; WhatsApp + Telegram в
одном приложении; «Авто» и «Вместе» (1–4 варианта); прайс фото/Excel/PDF/Word + каталог;
«Сводка» с 5 статусами; отдельная SIM не нужна (подключение по QR-коду или коду);
выключается одним касанием («Авто» на карточке бота) или тумблером канала; данные по HTTPS,
не продаются, без рекламных трекеров, удаление бота удаляет его прайс-листы, полное
удаление — по запросу; тарифы и цены из `PlanCatalog.cs`; пробный 5 дней / 150 диалогов /
без карты; оплата подпиской App Store / Google Play.
FAQ-ответ про «не знает ответа»: бот отвечает по вашему прайсу и каталогу; если нужного
нет — говорит клиенту, что уточнит, а диалог попадает в «Сводку» как «Нужен владелец»;
в «Вместе» без вашего выбора не уходит ни одно сообщение.

## Техника

- Исходники: `Tools/landing/src/` — `index.html` с маркерами секций, `sections/NN-*.html`,
  `css/*.css`, `js/*.js` (ES-модули). Сборка — один node-скрипт **без зависимостей**
  `Tools/landing/tools/build.mjs`: склейка секций в `index.html`, копирование ассетов в
  `Tools/landing/dist/`, версии файлов `?v=<хеш содержимого>` для кеша. Публикуется
  только `dist/`. `privacy.html`/`terms.html`/`favicon.*` — копируются как есть.
- Библиотеки — самохостинг в `assets/vendor/`: GSAP 3.13 core + ScrollTrigger (+ SplitText,
  если нужен), Lenis. Частицы — raw WebGL (без three.js). Шрифты — самохостинг woff2
  (subset кириллица+латиница), `preload` для основного начертания, `font-display: swap`.
- **Уровни качества** (`js/quality.js`, решение до старта анимаций):
  high — desktop/pointer:fine, WebGL, ≥ 8 ядер; medium — мобильные нормальные;
  low — `prefers-reduced-motion`, `saveData`, ≤ 4 ядра или deviceMemory ≤ 2, нет WebGL.
  low: статичный светящийся SVG-знак вместо частиц, без Lenis, без pin (простые reveal),
  лента остановлена. Runtime-регулятор: если скользящее среднее кадра > 24 мс ~1 с —
  урезать число частиц/DPR, затем выключить canvas.
- Все циклы rAF на паузе вне экрана (IntersectionObserver) и при `visibilitychange`.
  Анимировать только transform/opacity. DPR canvas ≤ 1.5. Картинки ниже первого экрана —
  `loading="lazy"` + `decoding="async"`, размеры заданы (CLS ≈ 0).
- Бюджеты (проверяются автоматически): JS ≤ 120 КБ gzip суммарно; вся страница до
  прокрутки ≤ 450 КБ; mobile 4× CPU — fpsAvg ≥ 55, p95 кадра ≤ 25 мс, кадров > 50 мс ≤ 3;
  LCP ≤ 2,5 с (desktop) / разумно на mobile-профиле; 0 ошибок консоли; нет
  горизонтального скролла на 360/390/768/1440. Сравнение всегда в паре с baseline v1 в
  том же прогоне (машина может быть нагружена).
- Мета: title/description, canonical, OG 1200×630 (новая, рендер из HTML-шаблона
  headless-Chrome), favicon/apple-touch из знака U9, JSON-LD `SoftwareApplication` без
  рейтингов, `lang="ru"`, `theme-color`.
- Доступность: контраст ≥ 4.5:1, видимый фокус, `prefers-reduced-motion`, семантические
  landmarks, демо управляется с клавиатуры, форма с label/aria-describedby.

## Форма заявки (контракт v1 — без изменений)

POST `https://n8n.choosereply.com/webhook/LandingLead`, тело form-encoded
(`URLSearchParams`, без CORS-preflight): `name` (опц.), `phone` (10–15 цифр, проверка на
клиенте), `website` (honeypot, пусто), `source=landing`. Ответ `{success:true}` /
`{success:false,error:"bad_request"|…}`. Во время разработки и проверок — **никаких
запросов к проду**: модуль формы берёт endpoint из `data-endpoint`, в локальных проверках
подменяется заглушкой (роут playwright). Реальная тестовая заявка — только после выкладки
и только с согласия владельца.

## Выкладка (только с отдельного «да» владельца)

1. Бэкап на VPS: `~/choosereply/site` → `~/choosereply/site.bak-2026-09-19` (cp -a).
2. Загрузка `dist/` поверх (rsync **без** `--delete`; `review/` не трогается).
3. Caddyfile сайта: `encode zstd gzip`; `Cache-Control` для `/assets/*` —
   `public, max-age=31536000, immutable` (URL версионированы), для HTML — `no-cache`;
   `caddy validate` → `caddy reload` (конфиг-файл тоже с бэкапом).
4. Проверки: 200 на `/`, `/privacy.html`, `/terms.html`, `/review/…`; сжатие в заголовках;
   стенд против боевого URL; визуально 390/1440.
5. Откат: вернуть `site.bak-…` и старый Caddyfile, `caddy reload`.
