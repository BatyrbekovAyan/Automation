## 2. What fails, in plan terms (§3 T5 «Тест сначала»)

- L1 (F1 §1.4) — after a re-pairing the app deletes by the CURRENT ids: the predecessor P1 (retired by Retire Same Bot
  Slot, deleted_reason NULL) keeps all seven tables of memory/history, its clone WFold keeps its 2 chunks and its stored
  original is never listed (`['f-new']` only); P1 stays reason NULL, nothing is booked — on HEAD this is exactly the
  orphan F1 §1.4 describes (WA and TG).
- L2 — the post-F1 line: the other channel's retired row (the T8 client no longer names it) and a key-less ancestor of
  the superseded chain keep their data and chunks; reasons stay liveness/trial_expiry; only Create's own 'replaced'
  booking exists. The second call with the retired ids then deletes them — i.e. on HEAD it takes a second,
  client-driven call per id to reach what the line reaches in one.
- L3 — the slot re-used after the delete: an older client's Create in the same slot adopts the deleted bot's predecessor
  (pred_profiles = [P1], replace_ids = [WFold]) — «переиспользованный слот после удаления бота» inherits the old chat.
- L4 / L6 / B1 — nothing is booked, a storage failure does not stop anything (List Bot Originals sees no file of the
  line), DBF_LINE_PARAMS does not exist.
- A1–A5, B1 — the sweep has no branch A (node «Clone Retirements» missing, Sweep Config has no retirementsDryRun).
- V1 — V12 Retired Clones picks a SUPERSEDED trial_expiry row (wa-s2) whose clone the line already booked.
- N1 — the guards pass copies that delete by the named ids only (verify-auth-gate, verify-history-handoff) and have no
  branch A to check (verify-clone-lifecycle: KeyError).
- L5 (legacy) passes on HEAD on purpose: it pins that the compat window keeps the pre-T5 behaviour.
