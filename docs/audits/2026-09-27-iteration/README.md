## Решения, принятые для исправления (инженерные; продуктовые компромиссы отмечены)

- **R1:** reauth-привязка только для профиля без владельца (`owner_id is null`), заявка живёт 1 сутки, `claim.status` никогда не шлёт код;
  плюс pairing должен быть инициирован самим заявителем через прокси (фиксируется в БД). Остаточное: неавторизованный наследуемый профиль может
  перепривязать тот, кто знает id и подключит свой номер (S6) — документируется.
- **R2:** привязка billing ID к установке (только формат `$RCAnonymousID:`), перехват разрешён у отозванной установки или у установки без живых
  ботов (восстановление после потери секрета: сначала claim ботов, затем billing ID переходит сам). Gate отказывает при `u=null`, Create требует
  непустой AppUserID в режиме сессии.
- **R4:** закрытие заявки/снятие паузы только применённой командой и только для заявок не новее версии команды; повторная отправка при открытии
  чата повторяет исходную версию. Остаточное: версия — часы телефона; при отставании часов нажатие «Авто» может не закрыть свежую заявку (безопасный отказ).
- **R7:** `send_unknown` оставляет ответ в памяти (для Wappi «неизвестно» обычно значит «доставлено, ответ потерян») и, с итерации 2026-09-28 (V6), помечает строку `delivery=unknown` (подтверждённая — `delivery=sent` + id транспорта); `send_failed` удаляет. Строку выбирает id выполнения (`Stamp Draft` сразу после агента), не текст; промпт модели не меняется.
- **R9:** зависший `send_pending` через 10 минут → `send_unknown` (планировщик уведомлений), без повторной отправки.
- **R14:** строгое толкование «не выбирай цену сам» (одна из конфликтующих цен без названного расхождения — провал).
- **R15:** проверяется опубликованная версия; для выключенного бота — черновик с явной пометкой, не ошибка.
