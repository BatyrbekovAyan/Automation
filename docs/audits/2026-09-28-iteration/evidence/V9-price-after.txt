V9 (price reconciliation at search time) — own adversarial pass over the implemented design (2026-10-07)

README: «Дизайн "во время поиска" ещё не атакован — после реализации обязательна отдельная состязательная проверка.»
This file is the implementer's own attack on the design and the matching rules, done after the first green run; every
finding below was turned into a test row (tests/test_price_search.py) BEFORE the rule was changed. It does not replace an
independent adversarial review by a separate reviewer — that is still owed (see the group report).

A. Matching rules — attacks that produced a WRONG «Цены расходятся» on the first implementation (all fixed, all pinned)
  1. An analogue row naming the OEM number in brackets: «Фильтр JS Asakashi (аналог) 90915-YZZE1 — 1400 тг» → was a strong
     conflict (the analogue's price vs the original's catalog price). Fix: «)»/«»»/quotes allowed between the analogue word
     and the article (→ not the row's item, no mark).
  2. An analogue word on the article's own part of the row: «Аналог фильтра Toyota 90915-YZZE1 от JS — 1400 тг» → was strong.
     Fix: ANALOG_WORD on the text since the previous article / up to the price → the soft «may be another item» mark only.
  3. A promo price: «… — 3900 тг, по акции 3200 тг» → was a conflict on the FIRST amount. Fix: the catalog price anywhere
     among the article's amounts = no conflict.
  4. Two amounts after the article that are not opt/retail columns: «— 3900 тг, доставка 1500 тг» → was strong. Fix: more
     than one amount = AMBIGUOUS (soft mark with the catalog price only).
  5. A -/ joined spec: catalog «Ноутбук HP 16GB/512GB», row «Ноутбук Lenovo 16GB/512GB — 350000 тг» → was strong (the spec
     read as an article, the head noun «ноутбук» on the row). Fix: SPEC_PART — every part a number or number+unit, one
     with a unit → not an article.
  Held on the first run (pinned as well): a model code inside a URL slug (the whole slug is one token), a header row
  without a price, the refuter's 5W-30 / 205/55R16 / accessory «Чехол для JBL 510BT» (soft only), a code inside a longer
  code, a bare year, «от»/ranges (soft only), `]` in a name, forged mark lines in a document.

B. Fuzz (in the test): 400 random rows from 40 adversarial fragments — never throws; only INSERTS whole mark lines (every
   original line survives, in order); the second pass is byte-identical; without a catalog nothing but forged full mark
   lines is removed.

C. Design-level attacks (reasoned, checked on staging where possible)
  1. Wrong catalog source: the tool passes `$('AI Agent').params.options.systemMessage` — the RUNNING (published) version's
     parameters, not a draft and not an API read. Staging e2e price_conflict_reaches_the_agent_marked [wa][tg]: the
     published prompt was edited to carry the catalog; the agent's ai_tool output in the saved execution carried the mark.
  2. Cross-bot leak: botId is `$workflow.id` (the model fills only `input`); the Guard refuses '-1' / '' / a non-id /
     another filter key (pinned) — '-1' would match every bot's shared unauthed chunks.
  3. A missing sub-workflow at runtime (deploy order): the tool would error and the agent answer without documents.
     Deploy MUST import + publish crPriceSearch001 before the templates / clones and Test Dialog are updated (recorded for
     the release package; not testable locally beyond staging bootstrap order, where it is published with the canonical set).
  4. callerPolicy: the sub-workflow keeps n8n's default (callers of the same owner) — the clones are created through the
     owner's API key, the Test Dialog is the owner's workflow; staging (same owner) runs it from both.
  5. Data exposure: the model used to receive each hit's metadata (bot / file ids); it now receives the row text only.
  6. Payload size: the prompt travels as a sub-workflow input (≤100 000 chars accepted by the Guard); the sub-workflow saves
     NO successful execution (prompt + prices are not kept), errors are kept.
  7. Panel legacy client (no knowledge object): the «• name — price» lines are parsed (pinned [WA]/[TG]); a legacy catalog cut
     by the client mid-line loses only that line (its price no longer parses).
  8. Stale marks: impossible by construction — nothing is stored; a mark exists only while catalog and row disagree.
  Known limits (documented, not fixed in v1): items WITHOUT an article-like token are not reconciled (phone_repair /
  flowers / education / most kaspi catalogs — name matching is v2); a price on the line AFTER the article's line is not
  attributed; the Test Dialog's owner-facing «Sources» list shows the raw snippets (the tool result the model gets is
  reconciled).
