---- journal note (verify design + refuter's corrections, as implemented) ----
1. BotTestSheet.Hide() bumps screenSeq (only when the panel is actually up): «Закрыть»/Android Back END the screen.
   A late answer after Hide no longer repaints the hidden panel, releases its busy latch, joins its history or calls
   RefreshReadiness/Handoffs; its verdict is still written under its own bot (alive + same target + newest).
2. BotTestResultPolicy.Decide: ApplyToScreen = ticket.Seq == currentSeq && botAlive. The target check stays a VERDICT
   condition only, on purpose: a live bot whose channel was unbound under the open sheet still gets its answer shown
   (the owner's own question, the same bot); refusing it would leave the sheet «Бот думает…» with Send locked.
3. «Unbound under the SHOWN sheet» is REACHABLE (not unreachable as the verifier wrote): BotSettings.OnEnable's
   get/status probe (no LoadingPanel, ~1 s) and the logout window write the «-1» sentinel into the open bot.
   RefreshReadiness() now re-decides the target from the bot as it is now (Show no longer resolves it separately),
   so after such an answer the readiness says «Канал не подключён» and the next send is refused locally — or goes
   through Telegram when Telegram still carries the bot.
4. Beyond the refuter's text, same root cause: OnSend calls RefreshReadiness() before it uses the target, so the
   MORE likely order (probe lands while the sheet is idle, before the owner presses Send) is refused locally too,
   instead of a request to the unbound profile/workflow that the server answers 403/502.
5. Orphan guard: the screen's own request whose bot was destroyed under the shown sheet (unreachable today: both
   DeleteBot callers sit under the sheet's modal backdrop) closes the sheet (Hide) instead of leaving it waiting.
   Pinned by PopupUI.HasOpenPopup (removed synchronously by PopupUI.Hide), not by parked.Count, per the refuter.
Client-only: no generator, canonical workflow, SQL or server contract changes; ships in the planned client build.
