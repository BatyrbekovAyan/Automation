# Поиск по прайс-листу «пропал» (29–30.10.2026): причина, замеры, исправление

Расследование по задаче из сессии «Фильтрация контактов бота»: e2e-шаг `retired_bot_reconnects_after_purchase` 29.10 утром
отвечал без поиска по прайсу. Всё ниже измерено на staging (n8n 2.36.7, тот же снимок модели, что на проде). Прод, Wappi,
Supabase и RevenueCat не трогались; на прод ничего не выкладывалось.

## Итог

- **Что было.** Клиент в «Авто» переспрашивает время и цену («Напомните, во сколько в пятницу вы привезёте букет «Нежность» и
  сколько он стоит?»). Цена есть ТОЛЬКО в прайс-листе (каталог пуст), время — в памяти чата. 12–17.10 этот шаг 8 раз из 8
  искал в прайсе и называл 18 500 ₸; 29.10 утром 6 из 6 ответил без поиска: «По цене букет «Нежность» уточнит флорист».
- **Наше не менялось.** Промпты, шаблоны ботов, Create, Price List Search, n8n 2.36.7 и текст e2e-сценария с пакета 17.10
  (`6a9d495c`) те же (поменялся только текст уведомления Channel Watch). Алиас `gpt-5.4-mini` и 13.10, и 29–30.10 отвечал
  снимком `gpt-5.4-mini-2026-03-17` — новой модели за алиасом нет, и закрепление снимка ничего бы не дало.
- **Причина.** В этом контексте решение модели «искать ли» стоит у границы, и на настоящем пути бота (n8n → LangChain →
  OpenAI) оно колеблется при ОДИНАКОВОМ входе: у всех снятых вызовов 4 795 входных токенов, сообщения байт в байт одни и те
  же, а ответы — то с поиском, то без. Утром 29.10 — 6 промахов из 6, ночью 29–30.10 — **21 из 50 (42 %)**. Правило «нет в
  каталоге — ищи в прайс-листах» в `_core.md` не говорило, что искать нужно и при переспросе, и когда в сообщении есть другие
  вопросы; фраза ниши «наличие подтвердит флорист при оформлении» становилась готовым шаблоном для «цену уточнит флорист».
- **Прод затронут** тем же образом: прод ходит тем же путём n8n → OpenAI. На проде не измерялось (живой трафик запрещён).
- **Исправление C2 (в каноне этой ветки, не выложено).** Одно предложение в `_core.md`, раздел «Цены и ассортимент», сразу
  после «нет в каталоге — ищи в прайс-листах.»:
  > Цену или наличие позиции, которой нет в «Products»/«Services», ищи в прайс-листах инструментом Supabase Vector Store до
  > ответа — и когда клиент переспрашивает или в сообщении есть другие вопросы.

  На настоящих клонах в одном окне времени: **16 из 16** с поиском против 8 из 16 без исправления (p ≈ 0.001); вместе с
  e2e на стенде с C2 — **19 из 20** (без C2 в ту же ночь — 29 из 50). Лишних заявок в отборе кандидатов — 0 (без
  исправления 7); весь авто-набор v1.8 ×3 — без регрессий (прохождение 252 → 257 из 273, лишние заявки 4 → 3, казахские
  18 → 21 из 27). Ответ ниши при расхождении цены каталога и прайса (правило V9) C2 не меняет: на клонах 0 из 16 ответов
  называют одну цену прайса и с C2, и без него (30.10 01:50–02:00). Готово к выкладке по «да» владельца.
- **Eval через прокси этот провал не видит.** Тот же вход через staging-прокси eval — **130 из 130** с поиском, при любых
  заголовках. Значит, eval через прокси переоценивает надёжность решений «вызвать ли инструмент» (поиск, заявка); такие
  решения нужно мерить на настоящих клонах (`real-path-probe.py`, ниже).
- **Первый кандидат (T, новое описание инструмента) отклонён:** поиск он чинил (16/16), но в сценарии, где владелец записал
  правило «скидок не даём», 10 раз из 10 открывал лишнюю заявку `create_handoff` (без него — 0 из 10). Это повтор урока T11c,
  теперь из описания инструмента: «Never answer … without calling it first» разрешило вызвать ДРУГОЙ инструмент.

| Гипотеза | Как проверено | Результат |

Почему колеблется именно настоящий путь, а прокси с тем же телом и заголовками — нет, не установлено: всё, что видно с нашей
стороны, совпадает (тело, заголовки, ключ, адрес, снимок, `service_tier: default`). На вывод это не влияет: решение сделано
надёжным там, где ходит бот, и измерено там же.

## Что осталось

- **Правило V9 о расхождении цен колеблется на настоящем пути у ботов на промпте ШАБЛОНА** (служебный бот стенда: утром
  2/2 называл расхождение, ночью 0/2), тогда как у ниш оно на клонах устойчиво (0/16 и 0/16, раздел 5). Отдельная задача —
  с тем же подходом: мерить на клонах (шаблонный промпт ниш не получает `_core.md`).
- **Eval через настоящие клоны.** Прокси не воспроизводит колебания решений «вызвать ли инструмент», поэтому такие решения
  нужно мерить на клонах. Сейчас для этого есть проба одного вопроса (`real-path-probe.py`); режим run-eval, который гоняет
  весь авто-набор через клоны стенда, — отдельная задача.
- **Причина разницы прокси / n8n** не установлена (таблица выше).
- **Ловушка стенда:** `bootstrap.py`, запущенный из git worktree без `Tools/n8n/.secrets/` (ссылки на файлы основной копии),
  перезапускает общий n8n стенда с пустым `CR_AUTH_SECRET` и только потом падает на входе — так было 29.10 в 23:16 (две
  минуты; исправлено повторным запуском со ссылками). Стоит, чтобы bootstrap отказывался до остановки сервера.
