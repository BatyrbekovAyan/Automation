# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Unity 6 (6000.3.9f1) C# mobile application for WhatsApp and Telegram bot automation. Manages chat interfaces, bot creation, and workflow automation with products, services, and messaging features. Targets iOS and Android via URP (Universal Render Pipeline).

## Build & Development

- **Unity version**: 6000.3.9f1 — open through Unity Hub
- **Rendering**: Universal Render Pipeline (URP 17.3.0)
- **Solution**: `Automation.sln` (auto-generated by Unity, gitignored)
- **NuGet packages**: managed via NuGetForUnity in "In Packages folder" placement — everything lives under `Packages/nuget-packages/` (`NuGet.config`, `packages.config`, `InstalledPackages/`). Keep NuGet files out of `Assets/`; the plugin reads `Packages/nuget-packages/NuGet.config` first and only falls back to `Assets/NuGet.config`
- **Git LFS**: enabled for binary assets (textures, audio, fonts, plugins) — see `.gitattributes`
- **Лендинг choosereply.com** (`Tools/landing/`, v2 с 2026-09): исходники `src/` → `node tools/build.mjs` → `dist/` (публикуется только dist); `npm test` (node:test) + `node tools/check.mjs` (headless-бюджеты, прод заблокирован, форма — заглушка); выкладка `tools/deploy.sh` (dry-run по умолчанию, без `--delete`, `review/` не трогать); цены в `src/js/pricing-format.js` зеркалят `PlanCatalog.cs`.
- **Icon lab** (`Tools/icon-lab/`): the app's own icon set — 6 business-tile glyphs + 4 nav tabs × outline/filled — is authored as hand-written SVG in `glyphs/*.svg`, the single source of truth. `node publish.js` renders them into the project; `python3 lint.py` checks the style contract in `STYLE.md` and *measures* each glyph (ink bounds, coverage, centroid) so the set stays a family by number rather than by eye; `preview.py`/`sheet.py` composite onto dark at true device size. Two rules worth knowing before touching it: the glyphs are white on transparency, so opening a rendered PNG directly shows white-on-white and reads as blank — always review through `preview.py`; and business glyphs are published *over* the existing `BT_*.png` filenames on purpose, because the `.meta` guid beside each one is what `BusinessTypes.asset` references. `Tools/render_business_icons.js` is now a thin delegate to `publish.js` (it used to hold its own copy of the geometry, which would silently overwrite the published icons).

- **Google Play track** (2026-09-06): everything repo-side is done — `docs/store/play-console.md` is the submission kit (owner steps: `androidKey`, upload keystore, EDM4U Force Resolve + commit, build; listing texts; App content / Data safety / IARC answers; Play products with ONE base plan each; device-pass list). Android manifest is custom (`Assets/Plugins/Android/AndroidManifest.xml`) and carries exactly ONE launcher activity — `UnityPlayerGameActivity`, matching `androidApplicationEntry: 2`; keep it in step if the entry point changes. It also sets `unityplayer.SkipPermissionsDialog` (2026-09-09): Unity otherwise asks for every dangerous permission in the manifest at first launch — on Android ≤ 12 a storage prompt before the onboarding, fed by the legacy `READ/WRITE_EXTERNAL_STORAGE` from the yasirkula AARs — while NativeGallery/NativeFilePicker request storage themselves at pick time. Play graphics: `python3 Tools/store/compose-listing.py play` (7 frames 1080×1920, Android chrome, SYSTEM Helvetica captions — SF Pro is licensed for Apple platforms only; the listing uses frames 01–06 — `07-plans` carries the iOS fine print «App Store» and ₸ prices, excluded 2026-09-08) and `python3 Tools/store/play-graphics.py` (feature graphic 1024×500 + icon 512) after `node Tools/icon-lab/appicon/android.js` (adaptive bg/fg layers from the shipped U9 vector).
- **Android system Back** is handled by `AndroidBackRouter` (zero scene wiring, `RuntimeInitializeOnLoadMethod`; Input System reports KEYCODE_BACK as `Key.Escape`): the pure `BackNavigation.Dispatch` walks `Targets()` TOP-MOST FIRST and acts on the first open surface with the SAME action its chevron/scrim performs — never a bare `SetActive(false)` (the auth back deletes pending profiles, Bot Settings reverts unsaved edits, item sheets discard an uncommitted card). Surfaces expose small hooks for it (`IsShowing`/`IsOpen` + a close: `PopupUI` keeps an open-stack with `TryCloseTop`, `BotSettings.HasOpenSheet/TryCloseTopSheet/RequestBack`, `Manager.IsAuthPageOpen/TryBackFromAuth`, `ProfileSubPages.HasOpenPage/TryCloseOpenPage`, …); `LoadingPanel`, onboarding and a mid-slide chat SWALLOW the press; the root backgrounds the app via `moveTaskToBack`, never `Application.Quit` (OnApplicationQuit is the PendingProfileLedger settle point). A new closeable surface must be added to `Targets()` in its z-order.
- **Android keyboard readers** (`KeyboardAwarePanel`, `FocusedFieldKeyboardLift`, `FormKeyboardScroll`, `FocusScrim`, plus the identical copies in `ItemEditSheet` and `KeyboardScrollFix`) measure the IME through the JNI visible-frame delta (`KeyboardInset`) and subtract `KeyboardLiftMath.BakedHomeBarCanvasPx` (92u) instead of `Screen.safeArea.y`, which is 0 under immersive Android. `TouchScreenKeyboard.area` is a ZERO rect while `.visible` is true on GameActivity (device-confirmed 2026-09-09), so the JNI path is the only source. **The 2026-09-09 device pass found every one of those readers had returned 0 on every Android device since they were written:** `android.graphics.Rect.top/bottom` are FIELDS and the code read them as methods (`Call<int>("bottom")` → `NoSuchMethodError`), which the bare `catch` swallowed — the composer slid under the IME (its partial rise was the suggestions slot's 780u fallback), sheets and forms never lifted. Fixed to `Get<int>` in all three copies; `AndroidRectJniGuardTests` is a source guard because EditMode cannot execute JNI. Note `dumpsys window` reports the IME WINDOW, which on Samsung is taller than the drawn keyboard (936 px vs 582 visible): trust the visible frame. Diagnostics for the next device pass compile only under the `CR_DIAGNOSTICS` define (`DevAndroidBuild`, below).

### Running EditMode tests

EditMode tests live in `Assets/Tests/Editor/Chat/` (no asmdef — they compile into the predefined `Assembly-CSharp-Editor`). Two ways to run them:

- **Editor closed (headless, hands-off)** — `Tools/run-tests-headless.sh` (Unity Hub can re-open the Editor on this project by itself after a reboot — the script refuses and names the pid; re-check before assuming the lock is stale). Launches Unity in batch mode (`-runTests -batchmode -nographics -testPlatform EditMode`, never `-quit`), parses the NUnit3 result, and writes outputs to `Tools/test-output/` (gitignored — must NOT be under `Temp/`, which Unity wipes on launch). Events: `OnChatAdded`, `OnChatListCleared`, `OnChatSelected`, `OnBatchMessagesLoaded`, `OnLiveMessagesReceived`. **Every send-path cache mutation must go through `LiveCacheFor` + `OutgoingSendCache` (2026-09-04), never a bare `ChatHistoryCache.LoadHistory`.** `_activeChatCache` is the list the D5 live poll hands to `SyncLatestMessages` as `cachedList`, and therefore the list `ReconcileGhostSend` searches when the server echoes one of our own sends back. All five send-path sites (text send + ack, media send + ack, media cancel) used to read-modify-write a DETACHED disk load, so the optimistic bubble was never in the list being searched: when the 3-second poll's echo beat the send's own ack — a coin flip, since `message/send` routinely takes 1–3s and does NOT hold the `_chatFetchesInFlight` gate that keeps the *polls* serial — the reconcile found nothing, returned false, and the merge read that false as «not a ghost recovery» and appended the echo as a SECOND bubble. Device symptom: a sent message rendered twice, a grey ✓ (the ack renaming the optimistic bubble) beside a ✓✓ (the poll's echo), deduplicating only on reopen, because the merge's `SaveHistory` wrote `[echo] + _activeChatCache` and so the disk file only ever held one row. Three things to keep in mind before touching this. (1) `OutgoingSendCache.Insert` is an ORDERED insert, not a `List.Add`: `_activeChatCache` is NEWEST-FIRST at every assignment site (`RecentMessageWindow` depends on it) and a just-sent message is the newest, so appending puts it at the wrong end. (2) `LiveCacheFor`'s guard needs BOTH halves — the chat must be the open one AND the snapshotted `cacheRoot` must still be the active bot's, because a send completing after a bot switch carries the originating bot's root while `_activeChatCache` has moved on. (3) A `false` from `AdoptServerId`/`ReconcileGhostSend` is load-bearing signal, not noise: it must only ever mean the bubble is genuinely uncached (evicted past the 100-message cap), never that the send wrote to a different list than the one being searched. The fix also repairs a silent second defect — the sent bubble's live ✓→✓✓ upgrade, which needed a cached entry to match `raw.id` against and so never fired in-session. Pure seam `OutgoingSendCache` pinned by `OutgoingSendCacheTests`. **Review hardening 2026-09-06 (four rules, all pinned):** the guard is the pure `OutgoingSendCache.UsesLiveList` and `LiveCacheFor` only delegates to it; the five sites write ONLY through `PersistSendCache`, which refuses a chat the owner deleted this session (`DeleteChat` marks, `RollbackDelete` unmarks) — a `message/send` ack landing 1–3s after «Удалить чат» used to rewrite the deleted chat's full history to disk; the ack announces `StatusToAnnounce` (never a hard-coded Sent that steps an echo-reconciled ✓✓ back to ✓); and the first-open (no-cache) callback runs `MergeOptimisticRows` so a send made while page 1 was in flight survives into `_activeChatCache`. `ReconcileGhostSend` goes through the seam's timestamp/sequence overload. `SendPathWiringTests` is a SOURCE guard: it brace-matches the five methods and fails if any of them touches `ChatHistoryCache` directly — the seam tests alone pass byte-identically against the pre-fix wiring.

(2) **The empty/error block is positioned, never resized.** `SuggestionsPanelBuilder` stretches those overlays over the card area, which handed the area's shrink to their `VerticalLayoutGroup`; with `childControlHeight` it lerps children from preferred toward MIN, and the two labels are plain TMP with a min of 0, so their rects collapsed while the glyphs kept drawing and the lines printed on top of each other. The runtime owns the chassis instead (`EnsureStateChassis` + `SuggestionStateLayout.TopOffset`): top-anchored with a `ContentSizeFitter`, centred while the area holds it, pinned to the area's TOP once it does not. **Row height chain (2026-08-18 fix).** The thread nests `Content` (VerticalLayoutGroup, `childControlHeight=false`, spacing 10) → row = `MessageText{Incoming,Outgoing}` root (HorizontalLayoutGroup + ContentSizeFitter) → `Bubble` (VerticalLayoutGroup + ContentSizeFitter). A layout group with `childControlHeight=false` sizes itself from `child.sizeDelta` — the child's size from the PREVIOUS pass — and `LayoutRebuilder.PerformLayoutControl` runs the row's fitter (an `ILayoutSelfController`) BEFORE descending to the bubble's, so the row shipped permanently one pass behind the bubble. It never self-healed: the dirty the bubble's resize raises lands mid-pass and `CanvasUpdateRegistry` drops it (that layout root is already queued, and the queue is cleared when the pass ends), so the mis-size survived until something unrelated dirtied the tree — which is why it read as "only some bubbles, only sometimes". Row too SHORT → the bubble overflows into the 10px inter-row spacing (**bubbles look glued to the next message**); row too TALL → `Tail`/`TailOutline` (ignoreLayout, anchored to the ROW's bottom edge at y≈16) hang below the corner (**detached tail**). Replies were the visible victims because they are the only bubbles whose height changes AFTER bind, via the async quote resolve. Two halves of the fix, both load-bearing — do NOT undo: (1) the row root's HLG carries `childControlHeight = true` so it reads the bubble's freshly computed preferred height in the same pass (`childControlWidth` stays FALSE — the bubble's own fitter owns width, and `AdjustTextBubbleSize`'s max-width clamps measure against that); pinned by `BubbleRowHeightLagTests`. (2) `HandleMediaRefreshed` must NOT skip the layout rebuild — it carries the quote resolution, and `ForceRebuildRoutine`'s deferred parent mark (a frame later, outside any layout pass) is the only rebuild request uGUI will not swallow. The client carries NO server-side credentials except the wappi token (per-install proxy planned) — see the n8n section.

## Additional Instructions

- All API calls use `UnityWebRequest` with coroutines (`IEnumerator` + `yield return SendWebRequest()`). Follow this pattern for any new network calls.
- Never hardcode API keys or tokens directly in source files. All secrets are loaded from `Assets/StreamingAssets/secrets.json` via the `Secrets` class (see `Secrets.cs`). Use `secrets.json.example` as a template. Since 2026-09-17 the file carries ONLY `n8nBaseUrl` + the RevenueCat public SDK keys — the Wappi token left the client with A1 (`Tools/store/inspect-artifact.sh` checks a real APK/AAB/IPA).
- When adding new API endpoints, follow the existing pattern: build URL with string interpolation, set auth header, send request, check `request.result`, parse JSON response with `JsonConvert.DeserializeObject`.
- Chat data flows through serializable model classes (`ChatDialog`, `NormalizedMessage`, `RawMessage`) — keep API response models in `Assets/Scripts/Chat/`.

## Conventions

- Singleton pattern for managers (`Manager.Instance`, `ChatManager.Instance`, `BotsPage.Instance`)
- MonoBehaviour with `[SerializeField]` for UI references
- PascalCase for classes, methods, and properties
- Prefab-based reusable components in `Assets/Prefabs/`
- Platform-specific code isolated in bridge classes (`AndroidBridge`, `IOSBridge`)
- TMPro for all text rendering
- DOTween for UI animations
- Bot entity persistence: `PlayerPrefs` keyed by `transform.name` (e.g. `Bot0Name`, `Bot0Products0`)
- Event-driven UI: views subscribe to `ChatManager` events rather than polling
- Partial classes for large components: see `BotSettings.cs` / `BotSettings.Auth.cs`
- **The UI ships in Russian only.** English/Kazakh are planned but there is deliberately NO localization
  layer yet (owner's call, 2026-08-19): every user-facing string is written in Russian at its site — in the
  scene, in the prefab, and in the C# that authors it. Three rules keep it that way:
  (1) **Never format a user-facing date/number through the ambient culture.** `ToString("dddd")`, `("MMM")`
  and friends read `CultureInfo.CurrentCulture`, which follows the DEVICE locale — an English phone printed
  English weekday separators inside the Russian chat. Go through `RuDateFormat` (and keep
  `CultureInfo.InvariantCulture` on the NUMBER wherever a decimal separator is formatted, e.g.
  `AttachmentDisplayFormat`). `DashboardTimeFormat` established this shape first.
  (2) **Counted nouns go through `RuPlural.Pick`,** never a hand-rolled `n == 1 ? … : …` — 11..14 take the
  "many" form despite ending in 1..4 (`UnreadSeparatorView`, the document bubble's page count).
  (3) **A visible label that is ALSO a logic sentinel must be a shared constant.** `ReplyParser.OwnSenderLabel`
  is the live example: `MessageItemView` colours the quoted card by comparing against it, so translating a
  hand-typed `"You"` at one site would silently drop the accent. `ReplyParser.IsOwnSenderLabel` also accepts
  the pre-RU `"You"` still sitting in `ChatHistoryCache` on older installs.
  (4a) **The SF Pro atlases need an SDF spread of ≥ 9 % of the sampling point size** (they are 112 pt /
  padding 12 since 2026-09-09; they shipped at AutoSize 224 pt / padding 5 = 2.2 %). TMP's Distance Field
  shader only anti-aliases while the spread covers ≥ 1 screen pixel (`scale ≥ 1`); below that the face
  alpha at the glyph quad's edge stays above 0 and EVERY small glyph draws a translucent box behind it.
  Threshold ≈ pointSize / (√2 · (padding + 1)) px of em — 45 px with the old numbers: the smallest labels on a
  1080-wide phone, nearly all body text on a 720-wide one (canvas scale 0.667), and invisible in the Editor
  and on iOS because their canvas scale keeps the em above it. Regenerate only through
  `SfProAtlasRegenerator`; `FontAtlasPaddingPremiseTests` pins the ratio and `_GradientScale = padding + 1`.
  (4) **An authored UI character must exist in the static SF Pro atlases.** All four SFProText SDFs are
  static 711-glyph atlases with NO fallbacks (TMP Settings global fallbacks are empty too), so a char
  outside the table renders as NOTHING and TMP only logs at layout time — «до −17%» shipped as «до 17%»
  (U+2212 minus, fixed to ASCII "-" in f4fe603) and the Support FAQ's «→» never rendered. Known-absent:
  − (U+2212 → use "-"), № (U+2116), ✕ (U+2715 → use × U+00D7), → (U+2192 → use › U+203A), ⇒, ∈, ✦, ⌨.
  Present and safe: - – — … « » ‹ › ' ' " " • · ₸ × NBSP. Only the LiberationSans chain (chat bubbles /
  TMP default font) is dynamic and can draw anything in LiberationSans.ttf. `FontGlyphCoverageTests`
  pins the whole class: every serialized label in Main.unity + Assets/Prefabs against its own font, and
  the copy seams (billing `*Rows`/`PaywallCopy`, dashboard labels, FAQ, prompt catalog) against SF Pro —
  extend its seam list when adding a new copy seam.
  Deliberately NOT translated: brand names (WhatsApp/Telegram/Instagram/n8n) and format acronyms (PDF/DOCX/GIF/QR);
  the hidden `Bot/Status` TMP, whose `"Active"`/`"Connecting.."` are a data channel `Bot.cs` reads (it paints the
  visible subline off `Status.color`, not the text); the dev-only n8n URL field; and every server-payload string
  (`Manager.ComposeBusinessKnowledge`'s `"About Business:"` + contact keys are an LLM-prompt contract, not UI).
  When you translate a scene/prefab label, translate the Editor builder that authors it in the same change —
  otherwise the next builder run silently reverts it.
